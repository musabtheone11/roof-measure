# Productive subscription case work

**Execution evidence:** the separate `roof-cloud-status/latest-work.json` journal records hosted work runs with their exact source revision, run link and task counts. The deployment source pin must include this runtime. Earlier model qualification, generated reports and image concepts do not establish that this queue has executed successfully.

## Qualification and productive work

| Operation | Purpose | Scope and maximums |
|---|---|---|
| `allowance-qualification` | Small compatibility screen | Three selected free text models; six-request ceiling. |
| `allowance-roster` | Refresh the free-model qualification record | All 23 registered free text IDs are assigned; 48-request ceiling and a 60-minute model phase. Availability, permanent circuits, remaining allowance and valid output determine actual coverage. |
| `allowance-work` | Investigate confirmed development-case failures | Generate 12 synthetic cases, create development-only packets, and select up to eight distinct case/question work items. A qualified author proposes a regression and an independently qualified reviewer challenges it. Prior safely undispatched backlog has priority; the combined batch is capped at 24 work items. The cycle has a 48-request ceiling and a 60-minute work phase; the current two-stage graph ordinarily needs at most 16 new stage calls for eight items. |

Qualification counts unique model IDs and validated role contributions. Productive work counts case/question items, author tasks, review tasks and proposals with independent review separately. A valid `needs-human` response is a contribution, not a transport failure or measurement approval. These counts must not be reported interchangeably.

## Workflow and admission

The application runs its existing trace engine on generated cases and produces reports before any case-work inference. The trusted packet adapter checks artifact paths, byte hashes, case identity, split membership and PDF readback. Only development cases enter model packets; validation and holdout cases remain outside them.

Five question families currently cover edge-fit drift, spurious physical roof segments, facet/edge topology, sloped-area fit and trace failures. Eight work items means eight distinct case/question pairs, not eight question families. Passing cases and obstruction-only diagnostic segments do not create artificial repair work.

Workers require retained, validated evidence for the exact free model and assigned engineering or critique role, a fresh authenticated roster and public catalog audit, and a compatible structured response protocol. An earlier response from another role is insufficient. An independent reviewer must differ from the author in model ID and named model family. Provider aliases do not establish independent evidence. Missing qualification or review leaves an explicit waiting state.

The queue shares the restored SQLite task, spending and weighted-allowance ledger with qualification and other laboratory operations. It permits only verified zero-dollar text routes: no paid model, image-generation or automatic paid fallback belongs to scheduled subscription work. Both author and reviewer need a durable weighted-allowance reservation before dispatch. Unknown outcomes retain their holds; zero wallet cost does not mean zero allowance use. Global authorization, permanent model circuits, quota cooldowns, cancellation and request/runtime limits remain effective.

Requests use the currently bounded structured/SSE policy, including an 8,000-token requested output window and a 120-second request deadline. Provider compliance and output validity must be measured; these settings are not guarantees. A timeout or incomplete response never triggers an unrecorded replay or repaired JSON acceptance.

## Deduplication and retained evidence

Work identity binds the measurement engine and generator hashes, property group, immutable case evidence and versioned question. Changing only the operator revision does not create another charge for the same question. Identical identities with conflicting numerical evidence fail closed. Assignments and author/reviewer task identities are durable, so restarting or resuming reuses the recorded task rather than redispatching it.

A demonstrably undispatched transient admission failure can receive one final acquisition after a delay. Its original assignment, evidence and measurement binding remain fixed. Dispatched or uncertain outcomes never take this path, and a model-specific blocked old assignment must not starve healthy models of new distinct work. Reviewer qualification may attach later when no reviewer was originally assigned; the author output is reused rather than regenerated.

`case-work.json` records stage counts, worker qualifications, waiting/failure states and proposal review outcomes. `case-work-evidence/` retains available packet and original author/reviewer artifacts in the downloadable report archive; the shared state keeps the authoritative task records and missing-evidence status. Models receive source-bound numerical facts and must preserve their exact values. A proposal or model review cannot mint test evidence, alter measurements, apply code, certify field accuracy or approve a production release. A later implementation requires its own independent tests and repository release process.

## Schedule and controls

The GitHub Actions schedule is configured to run `allowance-work` daily at **03:17 UTC** and `allowance-roster` weekly on **Sunday at 04:17 UTC**. Manual `workflow_dispatch` selections take priority; its default remains `cycle`, preserving the existing all-models behavior for an explicitly selected normal cycle. Runtime mode and the public journal profile derive from the same resolved operation, so subscription results stay in their scoped journal.

The global concurrency group serializes all branches, restores the latest verified checkpoint, and never cancels a possibly billed predecessor. State and report artifacts are retained under the existing policy. Hosted acceptance requires a complete case-work run, exact source pin, checkpoint continuity, zero paid/image dispatches, distinct work identities, independent review and truthful public counts. The run artifact and public work journal provide this evidence; this design document alone is not a claim of current service health.
